# Akochan の手牌探索と最終意思決定

本書は、現在の局面から次の行動を選ぶ仕組みを、手牌解析、候補生成、未知情報の扱い、将来価値の計算、出力という概念の順に説明します。本文では特定言語のデータ構造や制御構文を使わず、実装の識別子は末尾の「実装対応」に分離します。

固定重みの学習方法と外部 MJAI サーバーの検証は対象外です。実装固有の近似・上限・未使用設定は「実装上の境界」にまとめます。

## 1. 意思決定の全体像

AI は、判断点までのイベントを再生して局面を作り、次の順で候補を比較します。

| 段階 | 内容 |
|---|---|
| 状態の確定 | 最新の局開始からイベントを再生し、自分の手牌・副露・河・立直状態を得る |
| 形の解析 | シャンテン、待ち、和了形、役、符を求める |
| 候補の作成 | 打牌、リーチ、鳴き、槓、和了、パスと、その後の手牌状態を列挙する |
| 相手の推定 | 他家の聴牌、待ち、打点、局終了の可能性を確率化する |
| 将来の探索 | 残りツモと行動遷移から、和了・聴牌・放銃・降りの価値を求める |
| 順位価値への変換 | 局後の点数を4人の順位確率へ変換し、順位点期待値にする |
| 行動の出力 | 現在のイベントに対応する最良候補を MJAI イベントへ戻す |

比較の軸は、既定では順位点 (+90,+30,-30,-90) の期待値です。受け入れ枚数、打点、放銃率を別々に最大化するのではなく、局の結果を同じ尺度で比較します。

## 2. 入力と見えている牌

判断点は、自分のツモ、他家の打牌、他家の加槓です。自分のツモでは手牌にツモ牌を加えた状態、他家の打牌では13枚の状態、他家の加槓では槍槓を調べる状態として扱います。

牌は牌種の枚数へ正規化します。赤5は通常の5と同じ形の牌として数えますが、赤牌を持っているか、副露へ出したかはドラと出力のために保持します。

候補の牌山重みを作るときは、河、副露、表ドラなどの見えている牌から残り枚数を求めます。自分の手牌を残数から除く場合と、自分の副露だけを見える情報として扱う場合があり、目的によって使い分けます。残り枚数は実際の牌山の確率そのものではなく、候補状態の使用牌との差分も反映した探索上の重みです。

## 3. 先に作る終局価値

候補の探索を始める前に、和了と流局が起きた後の順位点を用意します。和了者、放銃者またはツモ、翻、符、親子、本場、供託の組合せごとに点数移動を求め、次局へ進んだ後の順位確率を評価します。流局では4人のテンパイ・ノーテンの組合せを評価します。

実装上は、親の連荘、リーチ供託、局の終了条件、同点時の座順をこの表へ反映します。これにより同じ点数の和了でも、序盤と終盤、トップ目とラス目で価値が変わります。

## 4. 手牌の解析

### 4.1 通常形

通常形では、雀頭、完成面子、未完成のターツ、孤立牌の組合せを列挙します。面子には刻子と順子があり、ターツには対子、両面、嵌張、辺張があります。各分解から、どの牌を1枚加えれば和了形になるかを求めます。

通常形の距離は概念的に「8 − 2×（完成面子数＋副露数）−ターツ数−雀頭数」です。4面子に達した場合の余り牌など、補正の詳細は実装境界として扱います。待ち牌が4枚すべて使われている場合は、その待ちを候補から除きます。

### 4.2 七対子

七対子は、対子の種類数を (p)、1枚だけの牌種数を (s) とすると、「13 − 2p − min(7 − p, s)」で距離を求めます。副露がある場合は七対子の経路を使いません。通常形と七対子の小さい方を総合距離にします。

共有ルール層と AI 探索層では距離の定義や利用目的が異なるため、数値を無条件に同一視しません。

### 4.3 和了情報

待ちごとに、ツモとロンを分けて翻・符を計算します。門前ツモ、門前ロン、暗刻、フリテン、ドラなどは、結果や経路によって扱いが変わります。役なしの形へドラだけを加えて和了可能にすることはありません。

同じ待ち牌が複数の分解で成立する場合は、役の違いを保持したまま複数候補として扱います。リーチ後の裏ドラは、見えていない牌の枚数を重みとする分布を使い、翻の上限まで和了価値へ反映します。

## 5. 手替わりと候補グラフ

### 5.1 状態と遷移

候補グラフの頂点は、正規化した手牌に、副露、赤牌の内外、立直、チー位置などの状態を加えたものです。辺はツモ、打牌、ポン、チー、槓、リーチなどの合法な遷移です。同じ牌姿でも状態が異なる場合は別頂点として評価し、同一状態の重複はまとめます。

14枚状態では、1枚捨てた状態を根にします。13枚状態では、現状維持と1枚引いて1枚捨てる交換を根にします。手替わりでは、将来引き入れる牌と外へ出す牌の組合せを列挙し、現在の牌・副露と合わせて同じ牌種が4枚を超える経路を除きます。

### 5.2 手替わりの範囲と優先度

非リーチ時の通常形の手替わり範囲は、現在の通常形距離に既定の追加幅 (2,2,1,1,0,0,0) を加えて決めます。七対子は通常形との距離関係に応じて別の上限を使います。

候補の優先度は、混一色、対々和、断么九、役牌になりやすい形を加点し、将来入力牌の残存組合せ確率を加えたものです。これは役の厳密な確率ではなく、膨大な候補を先に調べるための順序付けです。

### 5.3 鳴き・槓・リーチの制約

リーチ中は通常の手替わりを行わず、許された暗槓だけを調べます。鳴き牌と同じ牌種を直後に捨てる行動、チーの食い替え、鳴きに使った赤5を直後に同じ形で捨てる行動を除きます。候補グラフには、リーチ宣言後の状態を別頂点として追加します。

既定の全候補上限は200,000、1候補グループが保持する解析状態の上限は128です。上限に達した後の候補は追加されず、評価の完全性は保証されません。

## 6. 他家の攻撃と放銃リスク

他家について、まず聴牌している確率を求め、次に聴牌していると仮定した待ち・翻・符の分布を作ります。相手 (i) が牌 (h) で和了する条件付き量を (q_i(h))、そのときの順位価値を (v_i(h))、聴牌確率を (t_i) とすると、牌別の未補正危険度は「Σ (t_i q_i(h))」です。現行の単純合成では、この値を1で上限処理します。

相手ごとの分布は、リーチや副露が少ない場合は待ち形の係数、多い場合は見えていない手牌の組合せ列挙から作ります。待ち形の係数は両面の2端やシャンポンの2待ちを含む発生量で、必ずしも牌ごとの確率総和が1になるわけではありません。後段で条件付き分布と無条件の聴牌率を分けて合成します。

牌 h を切って放銃する確率を p(h)、放銃時の順位価値を V_deal(h)、放銃しなかった場合の将来価値を V_next(h) とすると、基本の打牌価値は (1−p(h))V_next(h)+p(h)V_deal(h) です。他家がその巡に和了して局が終わる確率も、同じ順位点尺度で合成します。

## 7. DP と非DP

### 7.1 適用範囲

既定では、通常の手牌距離が1以下なら DP、他家リーチ中は2以下なら DP を使います。鳴き判断では1以下、他家リーチ中の鳴き判断では2以下です。直前牌を鳴いた後の最良距離にも同様の判定を行います。

### 7.2 DP の考え方

DP は残りツモ回数を状態に持ち、流局や和了などの終端価値から現在へ戻します。牌 (h) の残り枚数を分母で割った重みで、引いた後に取り得る最良の打牌・鳴き・槓を比較し、牌ごとの値を平均します。候補状態の使用牌と現在状態との差分、赤牌、鳴き成立機会を加味するため、単純な「4枚−見えている枚数」だけでは一致しません。

各状態は、将来自分が和了する確率、終局時にテンパイしている確率、和了価値、総合価値、ベタオリ価値を持ちます。ツモ・打牌・ロン・ポン・チー・大明槓の遷移を順に比較し、他家の局終了を混ぜます。リーチ中の暗槓以外の行動、フリテンのロン、食い替えなどは遷移から除きます。

DP で使う残りツモ数は、物理的な70回のツモを座順へ割り当てて求めます。非DPでは、同じ物理値と統計モデルが推定する残りツモ数の小さい方を使います。

### 7.3 非DP の扱い

非DPでも候補グラフから将来のツモによる和了確率とテンパイ確率を求めますが、巡中の他家攻撃を DP と同じ位置では混ぜません。候補ごとの値を局結果（自分の和了、他家3人の和了、流局）へ渡し、そこで順位点を再計算します。

## 8. ベタオリ

ベタオリは、和了を追わず、安全そうな牌から必要枚数を切る方策です。同じ牌を n 枚持つときの安全度の減衰を 0.9^n とし、牌の危険度と放銃時価値を合わせて切る順を決めます。概念的な並べ替え係数は、放銃確率 p、放銃時価値 V_h、降りたままの価値 V_o に対し、「p(V_o−V_h)/(p+β−pβ)」、β=1−0.9^n です。

安全側から切るごとに、無事に次の牌へ進む確率と放銃時の価値を更新します。DP ではベタオリ価値が攻撃価値を上回り、未リーチなどの条件を満たす状態を降りへ置き換えます。非DPの自分のツモでは、他家リーチまたは大きな副露がある場合に攻撃とベタオリを比較します。

## 9. イベント別の最終選択

### 自分のツモ

低い手牌距離では、通常打牌、リーチ宣言、ツモ和了、設定で許可された暗槓・加槓を比較します。高い距離では、九種九牌、ベタオリ、孤立牌整理の順にルールベース方策を使います。ツモ和了には待ち、役、海底相当の補正、立直状態が必要です。

### 他家の打牌・加槓

低い手牌距離では、ロン、パス、ポン、チー、大明槓を比較します。加槓の直後は、槍槓を含むロンとパスだけを比較します。鳴き後の打牌についても放銃リスクを評価し、鳴く前の残りツモ数で計算した値と比較して小さい方を採用します。高い距離の非DP分岐では、明示的なロンを候補にしない設計です。

候補は `pt_exp_total` の降順で並べ、先頭を返します。現在切る牌の放銃リスクは候補の将来価値の外側で合成します。暗槓やツモ和了のように直ちに打牌しない行動には、現在打牌の危険度を掛けません。

## 10. MJAI への変換

内部候補は次の外部イベントへ変換します。

| 候補 | 外部表現 |
|---|---|
| 通常打牌 | `dahai` |
| リーチ | `reach` の後に `dahai` |
| ツモ和了 | `hora`（自分を対象） |
| ロン | `hora`（捨て牌者を対象） |
| ポン・チー | 宣言の後に `dahai` |
| 大明槓・暗槓・加槓 | 対応する1イベント |
| 九種九牌 | `ryukyoku` と `reason=kyushukyuhai` |
| パス | `none` |

リーチ、ポン、チーは宣言と直後の打牌を別イベントとして返します。受け手が1件目を受理してから2件目を送るプロトコルを前提とします。

## 11. 実装上の境界

以下は一般的な探索アルゴリズムではなく、現行 Akochan の挙動です。

- 高シャンテンのルールベース分岐は、未リーチかつ総合距離4以上、または通常形5以上かつ七対子3以上で入ります。設定に同名の項目があっても、この判定で参照されない場合があります。
- 候補数や解析状態の上限に達すると、警告なしに後続候補を落とします。
- 通常形シャンテン、牌の見え方、赤牌の扱いは共有ルール層と AI 探索層で完全には同じではありません。
- 他家の牌別危険度は相手間の独立性を使わず単純加算し、現在値だけ1で上限処理します。将来値では同じ上限がない経路があります。
- `ron_ratio_est` の回帰は実際のロン確率ではなく、DP の遷移比較用の相対係数です。`instant` ではポン・ロンの基礎係数だけを使います。
- リーチ後暗槓の判定には、牌姿の分解が変わらないことを使う近似があります。字牌を無条件に許すチェック単体など、呼び出し側の前提があります。
- 他家の加槓直後、ツモ総数70、フリテン全体判定、`out_moves` の一部の条件式には、標準ルールまたは手作り入力との違いがあります。
- 役距離の補助計算は、現在の意思決定経路へ自動的に加わるとは限りません。候補優先度と別の尺度を混同しないでください。

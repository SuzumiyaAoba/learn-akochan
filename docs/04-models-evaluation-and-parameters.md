# Akochan の推定モデル・期待値・パラメータ

本書は、見えない他家情報を確率分布へ変換し、和了・放銃・流局の結果を順位点期待値へまとめる考え方を説明します。確率モデル、牌の形の近似、順位評価を先に説明し、実装のファイル名・関数名は末尾の「実装対応」へ分離します。

固定重みの学習データ、学習手順、精度や校正の指標はリポジトリに含まれません。ここで説明できるのは、実行時にどの特徴をどの重みへ入力し、どの順で結果を合成するかです。

## この章のゴール

読み終えたら、次のことを説明できるようになることを目指します。

- 聴牌率・待ち・打点の条件付き分布を、牌別危険度へ合成する流れ
- 自分の和了、他家和了、流局を順位点期待値へ変換する流れ
- 固定パラメータを「学習処理」や「真の確率」と混同せず、実装上の境界を確認すること

前提は [02-state-rules-scoring.md](02-state-rules-scoring.md) の点数・局面と、[03-ai-search-and-decision.md](03-ai-search-and-decision.md) の候補・`pt_exp_total` です。ロジスティック回帰、softmax、期待値の記法は本章内で補足します。設定や接続の運用を確認する場合は [05-runtime-and-mjai.md](05-runtime-and-mjai.md) へ進んでください。

## 1. 全体の流れ

Akochan は、手牌の速さだけでなく、次の情報を同じ順位点尺度へ変換します。

| 入力・推定 | 出力 | 用途 |
|---|---|---|
| 河、副露、リーチ、手出し | 他家の聴牌確率 | 攻撃の有無を推定 |
| 牌の残りと手の形 | 待ち・翻・符の分布 | 牌ごとの放銃量を推定 |
| 自分の候補と残りツモ | 自分の和了・聴牌確率 | 候補の将来価値 |
| 局面と点数 | 流局・他家和了の確率 | 終局結果の分布 |
| 局後点数と残り局数 | 4人の順位確率 | 順位点期待値 |

この順で、条件付きの分布と無条件の確率を区別して合成します。例えば他家の牌別危険度は、聴牌確率と「聴牌している場合の待ち・翻・符の分布」を掛けて作ります。

## 2. 確率モデルの基本

### 2.1 二値確率

聴牌、和了、流局などの二値結果は、特徴量 x と重み w の内積をシグモイドへ通して求めます。式は P=1/(1+exp(−w·x)) です。切片を含むモデルでは x の先頭に1を置きます。

### 2.2 多クラス確率

順位の24通りの順列や、他家和了者の3通りは、各クラスのスコアを指数化して正規化します。クラス c の確率は exp(w_c·x) / Σ_j exp(w_j·x) です。これはクラス間の比率を作るためのモデルで、固定重みの統計的妥当性を保証するものではありません。

### 2.3 固定パラメータの契約

重みはモデルごとのテキストファイルから読みます。ファイルがない、必要数に満たない、設定されたモデル名が不明な場合は、既定値へ補完せず停止する経路があります。ファイル名に含まれる数字はファイル識別子であり、学習件数を意味するとは限りません。

確率を対数オッズへ変換する補助では、0以下を-10、1以上を10へ丸めます。したがって無限大の対数オッズではなく、有限値を回帰へ渡します。

## 3. パラメータの体系

現在の `params/ako` には、モデルを条件別に分けた固定重みが配置されています。実行時に使う軸と代表的な重み数は次の通りです。

| モデル群 | 主な条件軸 | 代表的な重み数 |
|---|---|---:|
| `tenpai_prob` | 副露数、河の長さ、通常手・染め手 | 5 または3〜5 |
| `tenpai_after` | 現在と将来の河の長さ | 2 |
| `other_end_prob` | 現在と将来の河、他家リーチ | 3 |
| `agari_prob` | 自分の河、他家リーチ、他家聴牌 | 4 |
| `my_keiten_prob` / `other_keiten_prob` | 流局時テンパイ | 3 / 2 |
| `ryukyoku_prob` | 自分の河、他家リーチ、他家聴牌 | 4 |
| `tsumo_num` | 自分の河、他家攻撃 | 4 |
| `houjuu_prob` | 他家和了時の放銃者分配 | 3 |
| `result_other` | 他家の和了者 | 21（3クラス×7特徴） |
| `rank_prob` | 局後点差、局番号 | 96（24クラス×4特徴） |
| `betaori` / `inclusive_fold` | ベタオリ時の放銃補正 | 3 |
| `ron_ratio` | DP の鳴き・ロン相対係数 | 3 または6 |

条件軸の範囲外では、河の長さなどを境界へ丸めたり、決定的な順位へ切り替えたりします。存在するファイルがすべて実行経路で使われるわけではありません。

## 4. 他家の現在状態

### 4.1 聴牌確率

リーチ済みの相手は聴牌確率1として扱います。`instant` モードでは副露数に比例させ、4副露で1とします。`ako` モードでは通常手と染め手を別に推定します。

染め手の色 c について、染め手である確率を s_c、染め手としての聴牌確率を t_c とすると、最終聴牌確率は「通常手成分 (1−Σ_c s_c)P_normal」と「各色の t_c」の合計です。色ごとの出力は再正規化しないため、モデル値の組合せによっては確率解釈に注意が必要です。

通常手モデルの特徴は、手出し枚数、他家リーチ後の打牌数、么九・字牌の種類数、中張牌の種類数などです。副露0では出力を最大0.12へ制限し、副露4では1とする境界があります。

### 4.2 待ち・翻・符の分布

リーチ中または副露のない相手では、実際の手牌を復元せず、両面・シャンポン・単騎・嵌張・辺張の形係数から分布を作ります。見えている牌、捨て牌、見逃し牌を候補から除き、残り枚数に応じて係数を弱めます。両面の2端やシャンポンの2待ちは発生量として数えるため、牌別配列の総和が1になるとは限りません。

副露相手では、見えていない牌から面子、雀頭、待ちを組合せ列挙します。各候補の重みは、牌種ごとの残り枚数から組合せ数を掛け合わせたものです。役なし、待ちなし、見逃しを含む候補は除き、和了形が少ない候補は重みを弱めます。これは隠れ手牌を完全に再構成する処理ではなく、放銃推定のための近似です。

推定する役には混一色・清一色、断么九、混老頭、字一色、純全帯么九・混全帯么九、対々和、三色、一気通貫、役牌、三暗刻、三槓子、大三元・小三元、大四喜・小四喜などがあります。リーチや一発などの相手の宣言情報は完全には復元しません。役がない形は分布から除きます。

### 4.3 条件付きから牌別危険度へ

相手 (i) が牌 (h) で和了する条件付き量を (q_i(h))、そのときの順位価値を (v_i(h))、聴牌確率を (t_i) とすると、牌別の未補正放銃量は「Σ (t_iq_i(h))」、放銃時価値は「Σ (t_iq_i(h)v_i(h)) / Σ (t_iq_i(h))」です。複数相手の危険度は、現行モデルでは独立確率の積を使わず単純加算し、確率だけ1で上限処理します。

副露手の列挙を条件付き分布へ正規化する経路では、最後に聴牌率を1回だけ掛けます。列挙重みと無条件の放銃確率を同じものと解釈すると、二重計上に見えるため注意してください。

## 5. 将来の他家状態

### 5.1 将来聴牌

将来の聴牌率は、現在と将来の河の長さを条件に推定します。`instant` は現在値を維持し、`ako` は現在聴牌率の対数オッズと切片を回帰へ入力します。リーチ済みの相手は1です。他家にリーチ者がいる場合、現行経路では非リーチ相手にもリーチ用の将来モデルを使うことがあります。

### 5.2 他家の局終了

他家がその時点までに和了して局が終わる確率は、非リーチ相手の「少なくとも1人が聴牌する確率」、他家リーチ人数、河の長さから推定します。少なくとも1人が聴牌する確率は、独立近似を置く経路では「1−Π(1−各相手の聴牌確率)」です。DP では各時点の終了確率を通常の進行価値と混ぜますが、累積ハザードを厳密に再正規化する処理ではありません。

### 5.3 鳴き・ロンの相対係数

DP の鳴き・ロン候補には、実際の成立確率ではなく候補比較用の相対係数を掛けます。基本係数は、ポン・ロンの候補フラグに応じて1倍または3倍です。`ako` では、ダマの待ち位置、リーチ状態、自分の聴牌率、牌別危険度、将来の他家聴牌を使ったオッズ補正を加えます。`instant` は基本係数だけを使います。

## 6. 自分の将来価値

### 6.1 和了確率

候補グラフから得た一人麻雀の和了確率を生値と呼びます。序盤で門前、他家リーチなし、他家副露が少ない条件では生値をそのまま使います。それ以外では、`instant` は0.5倍、`ako` は他家リーチ数、非リーチ他家の少なくとも1人が聴牌する確率、生値の対数オッズを回帰へ入力します。

和了価値は、和了と非和了が混ざった探索値から条件付き価値へ戻します。探索値を (V)、生の和了確率を (p)、非和了価値を (V_0) とすると、条件付き和了価値は「((V-(1-p)V_0)/p)」です。生値が0なら0とします。補正後の和了確率と生値から戻した価値は、同じモデルで再推定された組ではありません。

### 6.2 残りツモ数

残りツモ数は、物理的な山から座順で求める値と、河・他家攻撃から統計的に推定する値があります。非DPでは両者の小さい方を使い、DPでは物理的な値を使います。統計モデルが物理的な残りを超えることは許しません。

### 6.3 流局と形式聴牌

流局確率は、自分が和了しなかった場合の流局確率として扱います。`instant` は自分の河の長さから単純式で近似し、`ako` は自分の河、他家リーチ、他家聴牌をモデルへ入力します。形式聴牌は、自分がリーチ中なら1、他家がリーチ中なら1とし、それ以外を探索値または固定モデルで補正します。

4人の形式聴牌は独立なベルヌーイと仮定して16通りを列挙します。各パターンへ流局のノーテン罰符を適用し、局後の順位点を加重平均します。これは実際の手牌間の依存関係を再現するモデルではありません。

## 7. 局結果と順位価値

### 7.1 順位確率

局後の4人の点数から、1〜4着の確率を求めます。`ako` の順位モデルは、起家から見た相対座順での点差を1万点単位にし、切片を加えた4特徴を24通りの順位順列へ入力します。条件外では、点数順と同点時の座順から決定的な順位を返します。

### 7.2 和了・流局テーブル

和了者、放銃者またはツモ、翻、符、親子、本場、供託を組み合わせて点数移動を作り、局後の順位点期待値を表にします。5翻以上では符を区別しない表へまとめ、実現しない翻符の組合せは0にします。リーチ直後の仮想評価では、未受理の1000点を含む別の点数移動を使います。

流局は4人の形式聴牌を16通り評価し、親の連荘と次局の点数を順位モデルへ渡します。

### 7.3 5種類の局結果

局の結果は、自分の和了、他家3人の和了、流局の5種類です。自分の和了確率を (p_m)、流局確率を (p_r)、他家和了者の分布を (r_i) とすると、流局は「((1-p_m)p_r)」、他家 (i) の和了は「((1-p_m)(1-p_r)r_i)」です。各結果の順位点を掛けて合算したものが候補の最終期待値です。

他家和了者の分布は、`instant` では聴牌率の比率、`ako` ではリーチ有無と聴牌率を特徴とする3クラスモデルから作ります。和了者が決まった後の放銃者分布も別モデルで分配します。現行の `ako` 経路には、ファイルが3重みでも実際の回帰入力が2特徴になる境界があります。

## 8. ベタオリの価値

ベタオリは、牌ごとの危険度を並べ替え、必要枚数を安全そうな順に切った場合の期待値を近似します。同じ牌を複数枚持つときの減衰を 0.9^n とし、放銃確率 p、放銃時価値 V_h、降りた価値 V_o から、並べ替え係数「p(V_o−V_h)/(p+β−pβ)」、β=1−0.9^n を作ります。

牌を切るたびに、それまで無事だった確率、放銃確率、放銃時価値を更新します。`instant` では非和了価値をそのまま使い、`ako` では河や副露などからベタオリの放銃率を補正し、流局価値と他家終了価値を混ぜます。DP では攻撃価値よりベタオリ価値が高ければ状態を降りへ置換します。

## 9. 設定の境界

自己対局設定は4人分の戦術設定、MJAI 設定は1人分の設定を持ちます。候補数、DP、槓、降り、順位点、確率モデルの選択などを指定できます。

設定は、共通の戦術値として読み込む項目と、各モデルが設定 JSON を直接参照する項目に分かれます。設定キーを書いただけでは有効にならず、実際に呼び出し経路が読む必要があります。`base` の既定値は候補数と手替わり範囲を変えますが、候補グラフには別の静的上限があります。

現行設定で使われる代表的なキーは `jun_est`、`tenpai_prob_est`、`tenpai_after_est`、`other_end_prob_est`、`agari_prob_est`、`ryukyoku_prob_est`、`result_other_est`、`tsumo_num_est`、`houjuu_est`、`inclusive_fold_est`、`ron_ratio_est` などです。一方、設定として読み込まれるだけで、現在の主経路では計算に使われないキーもあります。

## 10. 学習処理との境界と別系統のシミュレータ

このリポジトリには、固定重みを読む推論処理だけがあり、学習データの母集団、目的関数、正則化、交差検証、精度評価はありません。`_nn` という名前のファイルがあっても、現行の順位推定でニューラルネットワークを実行するとは限りません。実行時に採用される計算経路を確認してください。

別系統の簡略シミュレータは、実牌やAIの行動を進めず、ツモ和了・ロン・流局と翻符を確率分布から抽選して次局の点数を作ります。実際のイベントをすべて生成する対局エンジンとは目的が異なり、通常の自己対局や MJAI 経路へ自動接続されているとは限りません。

## 11. 実装上の境界

以下はモデル一般の性質ではなく、現行実装を利用するときの注意です。

- 待ち形係数、相手間の危険度、形式聴牌の独立仮定は、確率の校正を保証しません。
- `instant` の固定式は物理的な局終了確率ではなく、候補比較用の近似です。
- `ako` の一部は条件付き分布と聴牌率を別経路で掛けます。正規化の位置を変えると値が一致しません。
- `cal_target_prob` 相当の和了者・放銃者分配には、読み込む重み数と実際に使う特徴数が異なる経路があります。
- 形式聴牌の流局評価は供託を点数移動へ渡さない経路があり、一般的な精算と同じとは限りません。
- 順位モデルは局番号・点数の条件外で決定的順位へ切り替わります。モデル値を全局面へ外挿しません。
- 設定名に `nn` や `new` が含まれていても、現行主経路で未使用の項目があります。
- パラメータファイルの欠落や不足は停止要因です。再学習や0埋めは行いません。

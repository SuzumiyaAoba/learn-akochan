# 状態・麻雀ルール・点数計算

本書は、MJAI のイベント列から現在の局面を復元し、待ち・役・符・合法な行動・点数移動を求める仕組みを説明します。説明の中心は牌と対局のロジックであり、特定の実装言語の型や文法には依存しません。

一般的なリーチ麻雀の説明と、Akochan が現在採用する実装仕様を分けて記述します。現行実装にだけ存在する境界や不整合は「実装上の境界」にまとめ、対応するファイルと関数を末尾に示します。

## 1. 処理の全体像

共有ルール層は次の順で処理します。

1. イベント列から最新の局開始を見つけ、そこから現在までを再生する。
2. 牌を牌種ごとの枚数へ正規化し、手牌・副露・河・立直状態を得る。
3. 手牌を分解して、シャンテン、待ち、和了形ごとの役と符を求める。
4. 直前イベントと局面を照合し、合法な打牌・鳴き・和了・パスを列挙する。
5. 和了または流局の結果を、親子・本場・供託を含む点数移動へ変換する。

状態復元は入力イベントの妥当性を証明する処理ではありません。記録に沿って状態を更新する処理なので、入力側でイベントの順序、牌の枚数、対象者を検証する必要があります。

## 2. 牌の表現

### 2.1 牌種と外部表記

内部では牌種ごとの枚数を扱います。外部の MJAI 表記と対応する番号は次の通りです。番号は実装との対応を確認するための識別子であり、アルゴリズム上の意味は牌種そのものです。

| 牌 | 番号 | 赤牌の番号 | MJAI 表記 |
|---|---:|---:|---|
| 萬子1〜9 | 1〜9 | 赤5萬=10 | `1m`〜`9m`, `5mr` |
| 筒子1〜9 | 11〜19 | 赤5筒=20 | `1p`〜`9p`, `5pr` |
| 索子1〜9 | 21〜29 | 赤5索=30 | `1s`〜`9s`, `5sr` |
| 東・南・西・北 | 31〜34 | なし | `E`, `S`, `W`, `N` |
| 白・發・中 | 35〜37 | なし | `P`, `F`, `C` |

赤5は通常の5と同じ牌種として比較できますが、ドラ計算や鳴きの表現では赤牌であることを残します。牌種への正規化は、赤5萬・赤5筒・赤5索をそれぞれ通常の5萬・5筒・5索へ戻す操作です。正規化後の枚数だけからは、どの1枚が赤だったかを復元できません。

物理牌を136個の識別子で扱う経路では、4枚の同一牌を同じ牌種へまとめ、物理識別子16・52・88だけを赤5として扱います。これは牌の意味を変える規則ではなく、乱択した山を牌種へ変換するための実装上の表現です。

### 2.2 副露とドラ

副露は、鳴いた面子の種類、鳴きの対象牌、手牌から消費した牌、捨て主の相対位置を持ちます。

| 種類 | 公開される面子 | 消費する手牌 |
|---|---|---:|
| チー | 上家の牌を含む順子 | 2枚 |
| ポン | 同じ牌3枚の刻子 | 2枚 |
| 大明槓 | 同じ牌4枚の明槓 | 3枚 |
| 暗槓 | 同じ牌4枚の暗槓 | 4枚 |
| 加槓 | 既存ポンへ同じ牌を追加 | 追加1枚 |

暗槓だけを行った状態は、門前として扱います。鳴いた人から見た捨て主の相対位置は、1が下家、2が対面、3が上家です。

ドラ表示牌から次のドラ牌を決める規則は、数牌では1から9へ循環し、字牌では風牌と三元牌のそれぞれの並びを循環します。ドラの数は、手牌と副露にあるドラ牌種、および赤5の枚数を合算します。暗槓では公開された牌の欄ではなく、消費牌の情報を使います。

## 3. イベント列から局面を復元する

### 3.1 局面の構成

現在局面には、場風、局番号、本場、供託、表ドラ、4人分の点数・自風・手牌・副露・河・立直状態が含まれます。自風は親を基準に座順から決まります。

局開始イベントに配牌、点数、親、場風、局番号、本場、供託、表ドラが含まれていれば、それを初期値にします。山全体がイベントに含まれていても、局面復元の入力としては配牌とイベント列を使い、山そのものを再生しません。

### 3.2 イベントによる状態変化

| イベント | 局面への反映 |
|---|---|
| `start_kyoku` | 局の情報と4人の初期状態を設定 |
| `dora` | 表ドラを追加 |
| `tsumo` | 指定された牌を行動者の手牌へ加える |
| `dahai` | 行動者の河へ追加し、手牌から同じ牌を1枚減らす |
| `reach` | 立直宣言を記録 |
| `reach_accepted` | 立直を成立させ、1000点を供託へ移す |
| `chi` / `pon` / `daiminkan` | 消費牌を手牌から減らし、副露を追加 |
| `ankan` | 4枚を手牌から減らし、暗槓を追加 |
| `kakan` | 追加牌を減らし、対応するポンを加槓へ置き換える |
| `hora` | 供託を消去する。和了点は局面へ直接反映しない |
| `ryukyoku`、`none`、局の開始・終了以外の管理イベント | 基本的な手牌状態を変更しない |

直近の局開始からイベントを再生するため、イベント列を別の局開始で区切れます。無効な牌は状態へ追加されず、再生処理だけでは枚数や順序の矛盾を検査しません。

### 3.3 後ろ向きに求める状態

立直成立、一発、フリテン、海底相当のツモ回数などは、現在までのイベント列を後ろ向きにも調べます。

- 一発は、自分の捨て牌が鳴かれた場合を含め、所定の中断イベントが現れると無効になります。現行実装では暗槓・加槓の扱いが一般的なルール説明と異なります。
- フリテンは牌種単位で過去の捨て牌と待ちを照合します。現在の待ちのうち1種類でもフリテンなら、現行のロン判定では全体を拒否します。
- 通常ツモと嶺上ツモを数え、終盤の行動に海底相当の補正を加えます。合法性、AI候補、自己対局の点数計算で境界が完全には一致しません。

## 4. シャンテンと待ち

### 4.1 待ち情報の作成

通常はツモ牌を含めない13枚の手牌と副露を入力として、次の処理を行います。

1. 赤牌を牌種へ正規化する。
2. 雀頭を選ぶ場合と選ばない場合を含めて手牌を分解する。
3. 刻子、順子、ターツを取り出し、残りが待ちを作る形かを調べる。
4. 牌山上で4枚すべて使用済みの牌種を待ちから除く。
5. 分解ごとに役と符を計算し、待ち情報として保存する。

残り1枚なら単騎待ち、残り2枚ならシャンポン・両面・嵌張・辺張を調べます。数牌だけが順子を作り、字牌は刻子または雀頭として扱います。同じ牌が複数の分解で待ちになる場合、分解ごとの役の違いを保つため、待ち情報は一つに潰さないことがあります。

### 4.2 七対子

七対子は、対子の種類数を (p)、1枚だけの牌種数を (s) とすると、距離を「13 − 2p − min(7 − p, s)」で求めます。副露がある場合、この専用計算は行いません。対子が6種類で単独牌がある場合は、単騎待ちとして待ち情報を作ります。

通常形の距離と七対子の距離の小さい方を総合値にします。ただし、共有ルール層の通常形の値は一般的な1シャンテン、2シャンテンを段階的に返す定義ではありません。主に即時の待ち検出と七対子との比較に使う値です。AI探索層の距離定義は文書04を参照してください。

## 5. 役と翻

### 5.1 和了情報

待ち情報には、待ち牌、待ち形、ツモ時の翻・符、ロン時の翻・符を保持します。ツモとロンで門前ツモ、門前ロン、暗刻の扱いなどが異なるため、同じ手牌でも別の値になります。

構造と牌種から判定する役には、役牌、門前清自摸和、平和、七対子、断么九、対々和、一盃口・二盃口、小三元、混老頭、三槓子、三色同刻、清一色、混一色、純全帯么九、混全帯么九、三色同順、一気通貫、三暗刻などがあります。清一色と混一色、純全帯么九と混全帯么九のように、上位役が成立したとき下位役を数えない組合せがあります。

代表的な翻数と判定条件は次の通りです。これは現在の共有ルール層が採用する値であり、別のルール設定を意味しません。

| 役 | 条件の要点 | 翻 |
|---|---|---:|
| 役牌 | 場風・自風・三元牌の刻子または槓子 | 1牌につき1 |
| 門前清自摸和 | 門前でツモ和了 | ツモのみ1 |
| 平和 | 門前、両面待ち、刻子なし、価値牌でない雀頭 | 1 |
| 七対子 | 7種類の対子 | 2 |
| 断么九 | 手牌・副露・待ちが2〜8の数牌だけ | 1 |
| 対々和 | チーなしで全て刻子または槓子 | 2 |
| 一盃口 / 二盃口 | 門前で同一順子が重複 | 1 / 3 |
| 小三元 | 三元牌2組が刻子、残りが雀頭 | 2 |
| 混老頭 | 么九牌・字牌だけで順子なし | 2 |
| 三槓子 / 三色同刻 / 三暗刻 | それぞれ槓子3組、同数字の3色刻子、暗刻3組 | 2 |
| 混一色 / 清一色 | 1色の数牌と字牌だけ / 1色の数牌だけ | 門前3/6、食い下がり2/5 |
| 純全帯么九 / 混全帯么九 | 全面子・雀頭が么九牌を含む / 么九牌または字牌を含む | 門前3/2、食い下がり2/1 |
| 三色同順 / 一気通貫 | 3色の同一順子 / 同一色の123・456・789 | 門前2、食い下がり1 |

ドラ、裏ドラ、立直、一発、海底、河底は、待ち情報を作る基本の役計算とは別の補正として扱われます。役がない形へドラだけを加えて和了可能にすることはありません。

### 5.2 役満相当と待ちの例外

清老頭、大三元、四槓子、九蓮宝燈、字一色、大四喜・小四喜、四暗刻などは、現行の点数表では13翻相当として扱います。三暗刻のシャンポン待ちで和了牌をツモった場合は、ツモ側だけ四暗刻相当となり、ロン側では完成した刻子が明刻として扱われます。暗槓を含む暗刻数や待ちの分解に依存するため、牌姿だけで一意に決まらない場合があります。

## 6. 符

平和と七対子は早期に符を確定します。現行の値は、平和がツモ20符・ロン30符、七対子がツモ・ロンとも25符です。

それ以外では、ツモ20符を起点に、面子、価値牌の雀頭、単騎・嵌張・辺張待ち、ツモ、門前ロンなどを加算します。明刻は中張牌2符・么九牌または字牌4符、明槓は8符・16符、暗刻は4符・8符、暗槓は16符・32符です。ツモには2符、門前ロンには10符を加え、30符未満は30符とします。

符の部品を一覧にすると次の通りです。

| 部品 | 中張牌 | 么九牌・字牌 |
|---|---:|---:|
| 明刻 | 2 | 4 |
| 明槓 | 8 | 16 |
| 暗刻 | 4 | 8 |
| 暗槓 | 16 | 32 |
| 価値牌の雀頭 | 2 | 2 |
| 単騎・嵌張・辺張待ち | 2 | 2 |

シャンポン待ちで和了牌が刻子を完成させる場合は、ツモ側では中張牌4符・么九牌または字牌8符、ロン側ではそれぞれ2符・4符として加えます。

符は部品の単純加算結果を返すため、10符単位に丸める前の32符や38符が残ることがあります。点数表は境界値で区分するため、標準的な丸めを前提にする呼び出し側は点数表へ渡す前に丸める必要があります。

## 7. 点数移動

### 7.1 和了点

和了点は翻・符・親子から決まります。5翻は満貫、6〜7翻は跳満、8〜10翻は倍満、11〜12翻は三倍満、13翻以上は役満相当として扱います。満貫以上の代表的なロン点は、子8000点、親12000点です。子のツモでは親が大きく、子2人が小さい額を支払い、親のツモでは全員が同額を支払います。

1〜4翻は符ごとの表を使います。翻0は0点で、表の範囲外の組合せは入力契約から外れます。

### 7.2 本場・供託

和了者への点数差を作るとき、本場はロンなら和了者と放銃者に300点単位、ツモなら和了者に300点単位、各支払者に100点単位で反映します。供託は1本1000点を和了者へ加えます。複数ロンを処理する呼び出しでは、同じ供託を二重に渡さないための抑制があります。

### 7.3 流局のノーテン罰符

流局時のテンパイ人数が1人ならテンパイ者が3000点を得て他3人が1000点ずつ払い、2人なら各1500点、3人なら各1000点を得ます。0人または4人なら移動はありません。本場と供託は流局の点数移動関数では扱いません。

## 8. 合法性と候補

### 8.1 二段階の検査

行動の検査は、外形と局面の二段階に分かれます。

1. 外形検査では、イベント種別、必須フィールド、消費牌の枚数、牌種関係、座順関係を確認します。
2. 局面検査では、直前イベント、手牌、副露、立直、ツモ回数、待ち、役、フリテンを確認します。

例えば、ポンの JSON が正しい形でも、手牌に同じ牌が2枚なければ合法ではありません。

### 8.2 単一イベント

| 行動 | 概念上の主な条件 |
|---|---|
| 打牌 | 自分のツモの直後。立直後は通常ツモ切りだけ |
| チー | 上家の捨て牌、順子を作る2枚、未立直、終盤でないこと |
| ポン | 他家の捨て牌、同じ牌種2枚、未立直、終盤でないこと |
| 大明槓 | ポンと同様だが同じ牌種3枚 |
| 暗槓 | 自分のツモ直後、同じ牌種4枚 |
| 加槓 | 自分のツモ直後、対応するポンと追加牌 |
| ツモ和了 | 自分のツモが待ちに一致し、ツモ側の役があること |
| ロン | 他家の打牌または加槓、牌が待ちに一致し、ロン側の役があること |
| 九種九牌 | 最初のツモ、河が空、全員未副露、么九牌・字牌が9種類以上 |
| パス | その時点で応答を省略するイベント。ただし入力経路により検査が弱い |

現行のロン判定は待ち全体を調べるため、当たった牌以外の待ちがフリテンでも拒否される場合があります。役の翻には、立直成立、海底相当、加槓へのロンの補正を加えますが、ドラや一発はこの判定に含めません。

打牌は自分のツモ直後にだけ行い、立直後は通常ツモ切りに限定されます。チーは上家の捨て牌、ポンと大明槓は他家の捨て牌を対象にします。暗槓と加槓は自分のツモ直後に行い、加槓では既存ポンと追加牌の対応も確認します。

### 8.3 宣言と打牌の組

リーチ、チー、ポンは宣言と直後の打牌を別イベントで表します。リーチは門前、1000点以上、未立直、終盤でないこと、打牌後にテンパイしていることが必要です。チーとポンでは消費牌を反映した後の打牌を検査し、チーの食い替えを禁止します。

合法な候補の基本的な列挙順は、ツモ切り、手出し、ポン、チー、大明槓、暗槓、加槓、リーチ、ツモ和了、ロンです。直前が他家の打牌なら、応答できるプレイヤーへパス候補も加えます。九種九牌は個別の合法性判定にはありますが、通常の候補集約には含まれません。

## 9. 実装上の境界

ここからは一般ルールではなく、現行実装を利用・再実装するときに確認すべき事項です。

- 状態復元は不正イベントを拒否する検証器ではなく、イベントを再生する処理です。和了イベントの点数配列も、同じ局面の点数へ反映されません。
- 共有層の通常形シャンテン値は段階的な一般シャンテン数ではありません。AI側には別の解析器があります。
- 共有層の待ち計算では、河や他家の見えている牌を残数へ入れません。AI候補評価では別の見え方を使います。
- チー・ポン・大明槓の一部の対象牌比較、赤5候補、海底付近の槓には、現在の入力形式では意図と異なる境界があります。
- 赤5を含む鳴きでは、通常5の捨て牌に対する赤牌消費の候補を別に列挙しますが、直前の捨て牌自体が赤5の場合に赤牌版が欠ける経路があります。
- 立直後の暗槓・加槓の制限、一発の無効化条件、ロン対象フィールドの検証は、一般ルールや外部サーバーの検証より弱い部分があります。
- 複数ロンは複数イベントとして記録できますが、支払いを累積した一般的な同時和了と同一とは限りません。
- 役満は複数役満としてではなく、点数表へ13翻相当として渡されます。

# Akochan ドキュメント案内

このディレクトリは、Akochan を一つのプログラミング言語の実装としてではなく、対局イベントを局面へ変換し、候補行動を順位点の期待値で比較する仕組みとして説明します。本文では麻雀・確率・探索・通信の概念を先に説明し、実装を確認したい場合だけ各文書末尾の「実装対応」を参照します。

ファイル名、関数名、設定キー、MJAI のイベント名は、実装や外部プロトコルを特定するための参照語です。これらの名前自体をアルゴリズムの定義とは扱いません。

## 推奨読順

1. [akochan-architecture.md](./akochan-architecture.md) — 入力から行動までの全体像
2. [03-runtime-and-mjai.md](./03-runtime-and-mjai.md) — 実行形態、イベント進行、外部連携
3. [04-ai-search-and-decision.md](./04-ai-search-and-decision.md) — 候補生成、探索、押し引き、行動選択
4. [05-models-evaluation-and-parameters.md](./05-models-evaluation-and-parameters.md) — 他家推定、確率モデル、順位価値
5. [02-state-rules-scoring.md](./02-state-rules-scoring.md) — 状態、牌・役・符、合法性、点数

必要な領域だけ読む場合は、状態とルールを確認したいときは02、AIの意思決定を知りたいときは04、推定モデルを知りたいときは05、起動や通信を知りたいときは03を選びます。

## 用語

| 用語 | 意味 |
|---|---|
| MJAI | 対局サーバーとプレイヤーが交換する JSON イベント形式 |
| イベント列 | 局の開始、ツモ、打牌、鳴き、和了、流局などを時系列に並べた記録 |
| 局面 | イベント列を再生して得られる、4人の手牌・副露・河・立直状態・点数など |
| 牌種 | 赤牌を通常牌と同じ牌として扱うときの種類。赤牌の有無は別情報として残る |
| 副露 | チー、ポン、明槓、暗槓、加槓によって公開された面子 |
| シャンテン | 和了までの距離。本文では、共有ルール層と探索層で定義が異なる場合を明示する |
| 待ち | 1枚加えることで和了形を完成できる牌種と、その形（両面など） |
| 順位点 | 局後の点数から順位へ変換した評価単位。既定値は1着90、2着30、3着-30、4着-90 |
| 候補グラフ | 手牌状態を頂点、ツモ・打牌・鳴き・槓などの遷移を辺とする探索表現 |
| DP | 残りのツモ回数を基準に、終端価値から現在へ期待値を戻す計算法 |
| `pt_exp_total` | 候補行動の局後順位点期待値。最終比較の軸 |

## 読み方と実装の境界

本文の数式は、確率の合成、期待値、牌の残数などを表すための記法です。特定の言語の文法やデータ構造を示すものではありません。イベント名・設定キー・ファイル名を示す場合も、それは外部契約または実装対応を識別するためです。

現行実装に固有の制約（複数ロンの精算、和了直後の点数反映、モデルの近似、入力検証の弱い箇所など）は、各文書で「実装上の境界」または「実装固有の注意」として概念説明から分離しています。一般的な麻雀ルールや統計モデルの性質と、Akochan が現在採用する近似を混同しないでください。

各文書末尾の「実装対応」には、概念を確認できるソースファイルと関数をまとめています。行番号は変更でずれるため、リンク先では関数名も併せて検索してください。

## 対象外

- ビルド手順は [`akochan/readme_jpn.md`](../akochan/readme_jpn.md) にまとめ、03では判断コアと実行アダプタの構成だけを説明します。
- 固定重みの学習データ、学習手順、精度指標はリポジトリに含まれないため、05では推論時の利用だけを扱います。
- JSON パーサーなどの汎用ライブラリの内部実装は扱いません。

`akochan/readme_jpn.md` は、Linux・Windowsでの依存ライブラリ確認とビルド手順だけを記した利用者向け README です。概念解説の6文書には含めず、実行前の補助資料として扱います。

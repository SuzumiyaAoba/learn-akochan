# Akochan の仕組み

Akochan は、対局のイベント列から現在の局面を再現し、可能な行動を将来の順位点期待値で比較する麻雀 AI です。本書では、特定の実装言語の型や制御構文ではなく、状態復元・ルール判定・探索・確率推定・意思決定の関係を説明します。

各節の説明は概念を先に置き、最後に「実装対応」として対応するファイルと関数を示します。実装固有の近似や既知の不整合は「実装上の境界」に分離しています。

## 1. AI が解く問題

麻雀の1手は、和了までの速さだけでは決まりません。手の高さ、他家へ放銃する危険、流局時のテンパイ料、現在の点差、残り局数を同時に考える必要があります。

Akochan は、これらを「局が終わった後の順位点」という一つの尺度へ変換します。既定の順位点は1着90、2着30、3着-30、4着-90です。候補ごとに、和了・他家和了・放銃・流局などの結果が起こる確率と、その結果後の順位点を組み合わせ、期待値が最も高い行動を選びます。

## 2. 入力から行動まで

処理は次の段階に分かれます。

| 段階 | 入力と出力 | 概念上の責務 |
|---|---|---|
| 1. イベント入力 | MJAI イベント列 | 対局の事実を時系列で受け取る |
| 2. 局面復元 | イベント列 → 現在局面 | 最新の局開始から手牌、副露、河、立直状態、点数を再生する |
| 3. ルール解析 | 局面 → 待ち・役・符・合法手 | 和了形と許される応答を求める |
| 4. 未知情報の推定 | 見えている情報 → 確率分布 | 他家の聴牌、待ち、打点、局終了などを推定する |
| 5. 候補生成 | 局面 → 行動候補と将来状態 | 打牌、リーチ、鳴き、槓、和了、パスを列挙する |
| 6. 将来評価 | 候補 → 順位点期待値 | ツモ、他家の攻撃、流局、局後の順位を合成する |
| 7. 出力 | 最良候補 → MJAI 応答 | プロトコル上の1件または2件のイベントへ戻す |

同じ局面復元と意思決定を、自己対局、ログレビュー、標準入出力、TCP 接続から利用できます。入力経路が違っても、判断の中心は同じです。

## 3. 局面の表現

局面は、4人の手牌・副露・河・立直状態に、場風、局番号、本場、供託、表ドラ、点数を加えたものです。対局の事実は可変の盤面だけで渡さず、イベント列として保持します。局を開始するイベントを起点に後続イベントを再生するため、自己対局と棋譜再生で同じ状態遷移を共有できます。

手牌は牌種ごとの枚数で扱い、赤5は通常の5と同じ牌種へ正規化できます。正規化した枚数は待ちや面子の判定に使い、赤牌の有無はドラ計算や鳴きの表現のために別に保ちます。副露は公開された面子と、手牌から消費した牌、捨て主との相対位置を含みます。

牌の残数は、河、副露、ドラ表示、自分の手牌など、すでに見えている牌を数えて求めます。ただし、共有の待ち計算と AI の候補評価では見える範囲が異なるため、文書02と04の定義を分けて読みます。

## 4. ルール判定の流れ

ルール判定は二段階です。まずイベントの種類、牌の個数、対象者など、形式的に矛盾していないかを調べます。次に、直前イベント、手牌、副露、立直、ツモ回数、待ち、フリテンを照合します。形式的に正しい行動でも、現在局面で許されるとは限りません。

和了判定では、通常形や七対子の分解ごとに待ちを調べ、役と符を計算します。ツモとロンは符や成立する役が異なるため、別の結果として保持します。点数移動では親子、本場、供託、ロン・ツモの支払者を加え、局後の順位を評価します。

## 5. 候補と探索

候補生成は、今の手牌を出発点として、将来引く牌・捨てる牌・鳴き・槓・リーチを状態遷移としてつなぎます。同じ牌姿でも、赤牌の内外、副露、立直状態、チーの位置が異なる場合は別の状態として扱います。重複する牌姿はまとめ、候補数には上限を設けます。

高いシャンテンの局面では、全ての将来を列挙せず、孤立牌の整理やベタオリなどのルールベース方策を使います。低いシャンテンの局面では、候補グラフを使って、残りツモ回数をさかのぼる動的計画法（DP）を適用します。DP を使わない場合も、将来のツモによる和了確率は候補間で比較しますが、他家の攻撃を合成する位置が異なります。

DP では、終局時の価値を起点に、残りツモが1回、2回と増える向きへ価値を戻します。各牌の残り枚数を重みとして、引いた後の最良の打牌または鳴き方を選びます。したがって、和了確率は「牌山から無条件に和了する確率」ではなく、その時点で最良と評価された方策を取り続けた場合の値です。

## 6. 他家の未知情報

他家の手牌は見えないため、次の量を分けて推定します。

1. その相手が聴牌している確率。
2. 聴牌していると仮定したとき、どの牌を待っているか。
3. その牌で和了した場合の翻・符と、局後の順位点。

副露やリーチの有無、河の長さ、手出しの特徴などから聴牌確率を求め、待ち形の係数または隠れ手牌の列挙から牌別の放銃量を作ります。相手ごとの放銃量を合成すると、現在切る牌の危険度と、放銃した場合の価値が得られます。

モデルの出力は実戦の真の確率ではありません。固定係数、形の近似、相手間の単純加算、流局時の独立仮定を組み合わせた推定値です。モデルの学習データや精度はリポジトリには含まれません。

## 7. 押し引きと順位価値

候補の価値は、局中の打点だけでなく、放銃と局終了を含めて計算します。直前に切る牌の放銃確率を p、放銃時の順位価値を V_deal、放銃しなかった場合の将来価値を V_next とすると、基本的な合成は (1−p)V_next + pV_deal です。他家がその巡に和了して局が終わる場合も、同じ尺度で混ぜます。

ベタオリでは、牌ごとの危険度と同じ牌を複数枚切るときの安全度の減衰を使い、安全そうな牌から必要枚数を切った場合の期待値を求めます。攻撃を続ける期待値よりベタオリの期待値が高い場合、候補の方策を降りへ置き換えます。

局の結果は、自分の和了、他家3人の和了、流局に分けます。和了時は翻・符・親子・本場・供託を点数移動へ変換し、流局時は4人のテンパイ状態からノーテン罰符を計算します。その後、点数と残り局から4人の順位確率を求め、順位点の期待値を得ます。

## 8. 出力と二段階行動

最良候補は、MJAI のイベントへ変換して返します。通常の打牌、ツモ和了、ロン、槓、パスは1イベントです。リーチ、チー、ポンは宣言と直後の打牌が別イベントになるため、1回の判断が2イベントとして返ることがあります。受け手は1件目を受理してから2件目を送ります。

候補が無い場合は `none` を返します。TCP、標準入力、1手 API では、二段階行動を保持する方法と入力イベントを記録へ反映する責務が異なります。運用上の違いは03で扱います。

## 9. 実装上の境界

以下は一般原理ではなく、現行の Akochan に依存する事項です。概念説明と混同しないでください。

- 共有ルール層と AI 探索層では、通常形シャンテンの定義と、見える牌を残数へ反映する範囲が異なります。
- 自己対局の山は136枚から作られますが、嶺上ツモの取り方や海底付近の合法性には実装上の簡略化があります。
- 複数ロンのイベント列は作れますが、後続の点数反映が一般的な同時和了の精算と一致するとは限りません。
- 和了イベントの `scores` は局面復元へそのまま反映されず、点数移動と次局開始イベントで扱われます。
- `instant` と `ako` は固定の近似モデルです。名前から学習方式や確率の正しさを推測できません。
- 一部の設定キーは、設定ファイルに書いても現行経路で参照されません。詳細は05の実装固有の注意を参照してください。
